## 摸清「提示词模板」功能结构（为后续优化做准备）

- 数据模型：`PromptTemplate{id,label(≤40),text,createdAt,updatedAt}`，定义在 `frontend/src/types/domain.ts`；Go 侧镜像 `shared/compat-go/state.go` 的 `PromptTemplate`。
- 纯逻辑层 `frontend/src/lib/promptTemplates.ts`：localStorage 键 `gptcodex.promptTemplates`、normalize/读取持久化、默认命名 `模板N`（第一个空位）、`resolvePromptTemplateManagerSelection`（new/selected 草稿初始化）。插入逻辑 `promptTemplateInsert.ts` 为「逗号追加」而非替换。

- 网站导入（prompts.sorry.ink）走 token：`useDesktopPromptImport` → `ImportPromptByToken` → `PromptImportModal`，只覆盖表单 prompt/negative/size，**不落成模板**。

## 实现「提示词模板」三项优化（已通过 tsc + 前端单测 + vite build）

1. **弹窗整体化**：`PromptTemplateManagerModal` 重写为单一外框 + 左侧列表(286px, border-r) + 右侧编辑区 + 底部固定操作条；`Modal` 传 `bodyClassName="p-0!"`（Tailwind v4 后缀 important，前缀写法已废弃），桌面居中由 `.app-modal-backdrop-desktop` 保证。草稿只在 open/切换选中时装载，`promptTemplates` 变化不再覆盖正在编辑的内容（用 `pendingDraftRef` 解决"保存当前"后 draft 被 effect 冲掉）。
2. **md 导入**：`<input type=file accept=".md,.markdown,.txt">` + `File.text()`（`ReadTextFile` 受 managedRawLogFile 限制，读不到任意路径，所以不能用宿主接口）。草稿非空时走行内确认条覆盖，不用 window.confirm。
3. **示例图**：`PromptTemplate.images`（`{id,path,imageId?,width?,height?}`，最多 2 张）。新增 `lib/promptTemplateImages.ts`：`pickPromptTemplateImage`（OpenImageDialog → 5MB 校验 → `ImportImagePathToImports`）、`resolvePromptTemplateImageSrc`（RegisterImportedImageAsset → /media/preview/<id>，失败回退 ReadImageAsBase64→dataURL，session 级缓存避免重复生成 AVIF）、`usePromptTemplateImageSources`。
4. **新增宿主能力** `backend/imports.go: ImportImagePathToImports(path, suggestedName)`：复制进 imports + 注册媒体。原因：`RegisterImportedImageAsset` 有 `ensureManagedReadablePath`，托管目录外的文件一律拒绝，直接引用用户原路径必然 404。Wails 绑定的是整个 svc，新增导出方法无需重新生成 wailsjs。
5. **ImageLightbox**（`components/common/ImageLightbox.tsx`，z-9300，高于 modal 9100 / popover 9050，Esc 用 capture 阶段 stopPropagation 防止同时关闭弹窗）。
6. **历史压缩**：`PromptPopover` 默认 5 条、单行 truncate、py-1.5，底部「展开剩余 N 条/收起」。
7. 跨端：`shared/compat-go/state.go` 加 `PromptTemplateImage` 与 `Images` 字段（Gio 端 Normalize 原样透传，不加会丢图）；Android 上传按钮显式禁用并提示「示例图暂支持桌面端」。

验证：`npx tsc --noEmit` 通过、`node --test test/promptTemplates.test.mjs` 9/9、`npm run build` 通过。**`go test` 未执行（本机无 Go）**，Go 侧改动仅人工核对。已知遗留：每次启动首次渲染会重新生成一份 AVIF 预览（`registerImportedPreview` 始终新建文件），previews 目录会缓慢累积。


## 新需求分析（未开发）

用户提出三条：①弹窗改「整体弹窗」；②新建模板支持导入 md 文档 + 上传 2 张示例图（单张 ≤5MB），选择模板时展示缩略图、点击放大；③历史列表压缩高度并支持展开/收起。

调研结论（关键约束，后续开发必须遵守）：
- 图片绝不能进 localStorage（5MB 配额 + AGENTS.md 禁止跨 bridge 传 base64）。桌面 `OpenImageDialog` 返回原路径 + `registerImportedPreview` 生成 `/media/preview/<id>`（AVIF）；Android bridge 会把选中图**复制到 importsDir** 并返回 path/size/imageB64/previewB64，**没有 /media 路由**，只能 `ReadImageAsBase64` 转 dataURL。
- `image-studio/backend/media.go` 的 `mediaAssets` 是**内存 map**，重启即空 → `/media/full|preview/<id>` 会 404。模板示例图必须在启动/打开弹窗时按 savedPath 重新 `RegisterImportedImageAsset` 重建。
- 无现成 lightbox 组件，需新建；`<input type="file">` 已有先例（`components/canvas/EmptyState.tsx`），md 导入走 `File.text()` 可跨桌面/Android 通用，无需新增宿主接口。
- 改 `PromptTemplate` 字段必须同步：`types/domain.ts`、`lib/promptTemplates.ts`（normalize）、`lib/compatState.ts`（build/apply）、`shared/compat-go/state.go`（Go struct），否则 Gio 端 `prompt_template_manager.go` 保存时整体覆盖会丢图。
- 初步发现的优化点：无排序/搜索/分组、无导入导出、草稿切换无脏提示、删除用 window.confirm、模板数量与文本长度无上限、新建位置三端不一致、内置模板常量重复、导入站点的提示词无法一键存为模板。
